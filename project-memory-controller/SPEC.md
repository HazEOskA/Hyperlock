# PMC Technical Specification v0.1

## 1. Purpose

Project Memory Controller protects a project state file from silent AI-driven contradictions.

## 2. Inputs

### 2.1 project.state.md
Human-readable source of truth.

### 2.2 STATE_UPDATE
Structured proposal generated by an LLM or user.

Example:

```yaml
STATE_UPDATE:
  add:
    ACTIVE_COMPONENTS:
      - validator
  remove:
    OPEN_ISSUES:
      - define_validator
  reason: "Validator scope has been defined."
```

## 3. Output

- updated `project.state.md`
- conflict report if validation fails
- change log entry if validation passes

## 4. Rules v0.1

| Rule | Description | Result |
|---|---|---|
| REMOVED_REUSE_BLOCK | Prevents adding removed components back into active state | Conflict |
| LOCKED_CONSTRAINT_BLOCK | Prevents changes that violate locked constraints | Conflict |
| RESOLVED_REOPEN_WARNING | Warns when resolved issues are reopened | Warning / confirmation |
| UNKNOWN_SECTION_REJECT | Rejects updates to unknown state sections | Conflict |
| EMPTY_REASON_WARNING | Warns when update has no reason | Warning |

## 5. Human Override

Conflict can be bypassed only with explicit override:

```yaml
OVERRIDE:
  approved: true
  reason: "Component is being reintroduced under a new architecture."
```

## 6. Non-goals v0.1

- no multi-agent orchestration
- no dashboard
- no cloud sync
- no permissions model
- no AI judge
