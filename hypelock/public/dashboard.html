STEP 01
SETUP & START
Wejdź do folderu projektu i uruchom w trybie PAPER (bezpiecznym):
cd ~/Hyperlock/hypelock npm install npm run paper
System startuje na porcie 3000. Dashboard dostępny pod:
http://localhost:3000
STEP 02
KONFIGURACJA TOKENÓW
Domyślnie system monitoruje: WIFBONKPOPCATPENGUMOODENG

Możesz zmienić przez zmienną środowiskową w .env:
WATCH_TOKENS=WIF,BONK,MYTOKEN,SOL
Lub dynamicznie przez API:
curl -X POST http://localhost:3000/tokens \ -H "Content-Type: application/json" \ -d '{"token":"NEWTOKEN"}'
STEP 03
ALPHA FILTER — JAK DZIAŁA
Każdy sygnał przechodzi przez 5 warstw filtracji:

L1 Bot pattern — wysoki ratio likes/komentarze, okrągłe liczby, nowe konta
L2 Spam keywords — "free airdrop", "100x gem", nadmiar hashtagów
L3 Velocity spike — engagement >5× powyżej baseline w 60s
L4 Source repetition — te same konta angażujące się wielokrotnie
L5 Coordination — 5+ aktorów synchronizujących akcje w 30s

Jeśli noiseScore > 0.65 → sygnał jest DISCARDED.
STEP 04
SCORING — DECYZJE
Po przejściu filtra sygnał jest scorowany (0-100):

EXECUTE effective score ≥ 75 → uruchamia trade
WATCH effective score ≥ 40 → monitoruj
IGNORE effective score < 40 → pomiń

Effective score = raw score × (0.5 + 0.5 × confidence)

Przetestuj zakładkę INJECT żeby zobaczyć jak różne sygnały są scorowane.
STEP 05
PAPER MODE vs LIVE MODE
PAPER Wszystkie EXECUTE są symulowane. Zero realnych transakcji. Logi pokazują estimated PnL.

LIVE Wymaga klucza Bankr API w .env:
PAPER_MODE=false BANKR_API_KEY=twoj_klucz
Następnie:
npm run live
⚠️ Upewnij się że system działa poprawnie przez kilka dni w PAPER zanim przełączysz.
STEP 06
INTEGRACJE API
Uzupełnij .env żeby odblokować realne źródła danych:

FARCASTER Utwórz konto na neynar.com → skopiuj Signer UUID i FID
X/TWITTER developer.twitter.com → App-only Bearer Token (read) + OAuth 1.0a (write)
ZORA zora.co/manage → API Key

Bez kluczy system działa w dry-run dla dystrybucji (logi co by opublikował).
STEP 07
API ENDPOINTS
Pełne API dostępne na localhost:3000:
GET /health → status systemu GET /signals → feed sygnałów GET /signals?action=EXECUTE GET /signals?limit=20 POST /evaluate → wstrzyknij sygnał GET /learning/status → wagi i learning GET /stats → pełne statystyki POST /tokens → dodaj token
STEP 08
DEPLOYMENT NA RAILWAY
Żeby uruchomić 24/7 na Railway:
1. Push repo na GitHub (już zrobione) 2. railway.app → New Project → GitHub 3. Wybierz HazEOskA/Hyperlock 4. Set Root Directory: hypelock 5. Ustaw zmienne środowiskowe w Railway 6. Deploy
Railway automatycznie wykryje npm start.
